# Бриф проекта: Учёт технического обслуживания автомобиля
## 1. Общие сведения
**Название продукта:** CarTrack 

**Краткое описание:** CarTrack - это сайт, где можно вести историю обслуживания автомобиля, записывать расходы и следить за состоянием машин.

**Целевая аудитория:** Автовладельцы, которые хотят контролировать расходы на машину и не забывать вовремя менять расходники (масло, фильтры, колодки).

## 2. Функциональные требования
**Обязательные (MVP):**
1. Пользователь может выбирать один из трёх заранее заданных автомобилей: Skoda Octavia A5, Lada Priora 2011 или BMW M5.
2. Пользователь может просматривать историю обслуживания выбранного автомобиля.
3. Пользователь может добавлять записи об обслуживании и ремонте, указывая дату, пробег, описание работ и стоимость.
4. Программа автоматически подсчитывает общие расходы на выбранный автомобиль.
5. Пользователь может добавлять запчасти к записи обслуживания, указывая название, количество и цену.
6. Программа отображает напоминание о замене масла на основе текущего пробега и пробега последней замены масла.

## 3. Нефункциональные требования
*   **Язык интерфейса:** Русский.
*   **Производительность:** Время отклика интерфейса — не более 1 секунды при стандартных операциях.
*   **Хранение данных:** Локально в файле БД (SQLite), сеть не используется.
*   **Защита от ошибок:** Система не позволяет сохранять записи с отрицательными: пробегом, стоимостью или количеством запчастей.
*   **Инициализация БД:** При первом запуске приложение само создает таблицы из встроенного SQL-скрипт

## 6. Сценарии использования (Use Cases)

### Сценарий 1. Добавление записи об обслуживании

**Актёр:** Пользователь.

**Предусловие:** В системе есть три автомобиля: Skoda Octavia A5, Lada Priora 2011 и BMW M5.

**Основной поток:**

1. Пользователь выбирает автомобиль из списка.
2. Нажимает кнопку «Добавить запись».
3. Система открывает форму добавления записи.
4. Пользователь вводит дату, пробег, описание работ и стоимость.
5. Пользователь при необходимости добавляет запчасти, указывая название, количество и цену.
6. Пользователь нажимает кнопку «Сохранить».
7. Система сохраняет запись и обновляет историю обслуживания и общие расходы выбранного автомобиля.

**Альтернативный поток:** Если пользователь ввёл отрицательный пробег или отрицательную стоимость, система показывает сообщение об ошибке и не сохраняет запись.

### Сценарий 2. Просмотр истории обслуживания

**Актёр:** Пользователь.

**Предусловие:** В системе есть выбранный автомобиль.

**Основной поток:**

1. Пользователь открывает главный экран сайта.
2. Выбирает один из трёх автомобилей.
3. Система отображает историю обслуживания выбранного автомобиля.
4. Пользователь просматривает даты, пробег, описание работ и стоимость.
5. Система показывает общие расходы на выбранный автомобиль.

**Альтернативный поток:** Если записей об обслуживании нет, система показывает сообщение «История обслуживания пуста».

### Сценарий 3. Проверка напоминания о замене масла

**Актёр:** Пользователь.

**Предусловие:** Для выбранного автомобиля есть данные о текущем пробеге и последней замене масла.

**Основной поток:**

1. Пользователь выбирает автомобиль.
2. Открывает раздел с напоминанием о замене масла.
3. Система сравнивает текущий пробег с пробегом последней замены масла.
4. Если подошёл срок замены масла, система показывает напоминание.
5. Пользователь видит, сколько километров прошло после последней замены масла.

**Альтернативный поток:** Если данных о пробеге нет, система сообщает, что недостаточно данных для напоминания.
